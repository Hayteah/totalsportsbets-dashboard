## 2026-07-17 - Semantic and Keyboard-Accessible Switches
**Learning:** Custom interactive wrappers (e.g., `div` elements) act as silent barriers for assistive technologies and keyboard users, even if they look like toggles/switches. Transitioning them to standard, semantic HTML elements (like `button`) with appropriate ARIA properties (`role="switch"`, `aria-checked`, `aria-label`) restores native tab sequencing, accessibility, and focus styling, resulting in a robust micro-interaction.
**Action:** Always start interactive UI controls (such as toggles, buttons, and custom triggers) with semantic interactive HTML elements like `<button>` rather than generic containers (`<div>`). Reset native button styles explicitly and handle keyboard focus states cleanly to merge custom aesthetics with absolute accessibility.
